01 The technical foundation

The application is built on a proven, production-grade stack — the same technology behind the ExportKit marketplace app — so it's fast, secure, and deploys automatically. Here's what has been set up and wired together.

Frontend · Next.js
A modern React (Next.js) application that embeds directly inside GoHighLevel as a menu page. Same framework used across our marketplace apps.
Backend · Node.js
A Node.js service handles secure login verification and session management — the shared secret and account checks live here, never in the browser.
Database · Supabase
A Supabase (Postgres) database with per-account isolation and access rules already in place, ready to store sessions and app data securely.
Authentication
Automatic, silent login inside GoHighLevel — the app identifies the exact sub-account and user, verifies them server-side, and issues a secure session.
Hosting · Vercel
Deployed on Vercel with automatic builds on every code commit — no manual steps, and no vendor lock-in to a visual builder.
Per-account isolation
One deployment per sub-account (BGD, Veritas, Omnia) — a request physically cannot reach the wrong account.

02 Security model — two walls

GoHighLevel's new AI connection routes everything — including deletes and bulk messaging — through a single channel. So protection is enforced in two independent layers; if one had a flaw, the other still holds.

Outer wall · GoHighLevel
The access token is granted only contacts + opportunities permissions. Nothing else is even reachable.
Inner wall · Our proxy
Deny by default. Only an explicit approved list of actions passes — anything unrecognised, plus deletes and bulk SMS/email, is refused.
Agreed scope

Contacts and opportunities — read and write. No deletes. No bulk SMS or email. Enforced in the build, not just promised on paper. Final action list to be confirmed together before go-live.

04 What the AI can answer — and what needs Phase 2

The live CRM connection is excellent for the "right now" questions. Historical trends are a separate data problem — which is exactly what the pipeline tracking tool (PipelinePulse) already handles.

Question typeExampleCovered by
Current state"Show contacts tagged hot lead" · "What's in Proposal Sent?" · "Mark this deal Won"Live connection — Phase 1
History & trends"How long do deals sit in each stage?" · "Conversion this quarter vs last?"PipelinePulse — Phase 2
Why the split

GoHighLevel's connection only knows the current state of a record — it doesn't store how things changed over time. That history is precisely what PipelinePulse was built to capture, so it comes in as an additive second phase.
